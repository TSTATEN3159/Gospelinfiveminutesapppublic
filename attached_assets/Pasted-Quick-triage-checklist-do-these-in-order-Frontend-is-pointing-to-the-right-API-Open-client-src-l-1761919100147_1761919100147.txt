Quick triage checklist (do these in order)

Frontend is pointing to the right API?
Open client/src/lib/api-config.ts (or wherever your apiUrl() lives). Confirm:

Dev: http://localhost:5000 (or your dev URL)

Prod (iOS/TestFlight): https://daily-gospel-timothystaten.replit.app
If this changed during the “dynamic” update, the app will fetch from nowhere.

Capacitor allowNavigation includes your backend
In capacitor.config.ts (or capacitor.config.json):

server: {
  allowNavigation: [
    "daily-gospel-timothystaten.replit.app",
    "youtube-nocookie.com"
  ]
}


If missing on iOS, requests may silently fail in the WebView.

CORS still allows your app
In server/routes.ts (or server/index.ts), ensure:

import cors from "cors";
app.use(cors({
  origin: [
    "capacitor://localhost",
    "http://localhost",
    "http://localhost:5173",
    "https://localhost",
    "http://127.0.0.1",
    "https://daily-gospel-timothystaten.replit.app" // backend can call itself
  ],
  credentials: true
}));


If Replit’s change tightened CORS, TestFlight requests will fail.

Database migrations applied?
Dynamic content usually adds tables/columns. Run on Replit shell:

npm run db:push --force


If the new “devotionals / reading plans” tables don’t exist, API returns empty/500.

Seed the new dynamic content
If the DB is empty, your API will “work” but return nothing. Add a tiny seed now:

Add to server/routes.ts (near bottom, behind a key):

  if (process.env.SEED_KEY !== req.query.key) return res.status(403).json({success:false});

Then set SEED_KEY secret in Replit and hit:

curl -X POST "https://daily-gospel-timothystaten.replit.app/admin/seed-devotionals?key=let_me_in_123"


(Replace with your actual table/column names.)

Option B – SQL/Drizzle seed script
If you already have /scripts/seed.ts, run it:

npm run seed


Verify the API returns data (before touching the app)
Try your real endpoints. For example (adjust to your routes):

curl -s https://daily-gospel-timothystaten.replit.app/api/devotionals/today | jq .
curl -s "https://daily-gospel-timothystaten.replit.app/api/reading-plan/today?plan=bible-in-1-year" | jq .


Expected: real JSON with a title/passage/body and today’s reading set.

Confirm the client expects the new JSON shape
If Replit changed payloads (e.g., data.items[] → data[] or renamed fields), your UI will render nothing.

Search your client for the fetch: getDevotional, getReadingPlan, or wherever it loads devotionals.

Compare expected fields in TypeScript (e.g., title, passage, body, dayNumber) with what the API actually returns.

Hotfix: map the new payload to the old shape in your data service so the UI doesn’t break:

// bibleService.ts (example)
export async function fetchDevotional() {
  const res = await apiRequest("GET", "/api/devotionals/today");
  const data = await res.json();
  // Adapt dynamically if format differs
  const d = data.devotional ?? data;
  return {
    title: d.title ?? d.heading ?? "Daily Devotional",
    passage: d.passage ?? d.reference ?? "",
    body: d.body ?? d.content ?? ""
  };
}


Add a graceful fallback (prevents blank screens in prod)
In the UI component that shows today’s devotional/plan:

Try API → if it fails, show last cached content from localStorage

If no cache, show a bundled static “Daily Devotional Unavailable” with a verse
This way TestFlight never looks “empty” again.

2) Typical root causes we just covered

API base URL switched (client now pointing to localhost in prod).

CORS/ATS/allowNavigation mismatch after file changes.

DB migrations not applied (new tables exist only locally).

DB not seeded (API returns 200 with empty arrays).

Response JSON shape changed (TypeScript types no longer match; UI renders nothing).

Date/timezone filters (e.g., using UTC midnight so “today” filters out content). If so, query by range:

WHERE date BETWEEN (now() AT TIME ZONE 'America/New_York')::date
                AND (now() AT TIME ZONE 'America/New_York')::date


or compute the local date server-side and store as date-only.

3) One-button fallback switch (optional but powerful)

Add an env flag to the client:

// api-config.ts
export const FEATURE_DYNAMIC_CONTENT = import.meta.env.VITE_FEATURE_DYNAMIC_CONTENT === "true";


Use it in your data service:

if (!FEATURE_DYNAMIC_CONTENT) {
  return STATIC_DEVOTIONAL_OF_THE_DAY;
}


Then set VITE_FEATURE_DYNAMIC_CONTENT=false in .env.production for a quick “static fallback” while we fix prod data.

4) After it’s fixed

Rebuild in Appflow → TestFlight → verify

Keep the fallback + cache logic in place so future API hiccups don’t blank the screen.
