1) Verify the proxy wrapper HTML + headers

Show the route code around the proxy:

rg -n "youtube-proxy" -n server/routes.ts
sed -n '1,260p' server/routes.ts | sed -n '2150,2300p'   # adjust if needed


What we expect in that route:

<iframe src="https://www.youtube-nocookie.com/embed/${videoId}?playsinline=1&rel=0&modestbranding=1">

No autoplay=1 and no enablejsapi=1 (those can trip 153 on iOS)

Response headers: just Content-Type: text/html; charset=utf-8 and Cache-Control: no-store (no CSP, no X-Frame-Options)

Check the prod headers:

curl -I https://daily-gospel-timothystaten.replit.app/youtube-proxy/M7lc1UVf-VE


We want to see:

HTTP/2 200

content-type: text/html; charset=utf-8

cache-control: no-store

No content-security-policy

No x-frame-options

Check the embed URL actually rendered:

curl -s https://daily-gospel-timothystaten.replit.app/youtube-proxy/M7lc1UVf-VE \
  | grep -A2 "<iframe"


We want: www.youtube-nocookie.com/embed/... ?playsinline=1&rel=0&modestbranding=1

2) Make sure iOS won’t block navigation to your own proxy page

If you don’t see it, add:

  'https://daily-gospel-timothystaten.replit.app',
  // (keep your existing YouTube domains)

3) Confirm WKAppBoundDomains is NOT sabotaging us

If this key exists and doesn’t list your proxy domain and the YouTube domains, iOS will block the iframe.

grep -n "WKAppBoundDomains" ios/App/App/Info.plist || true


If nothing prints → good (skip).

If it exists, ensure the array includes all of these:

daily-gospel-timothystaten.replit.app

youtube-nocookie.com

youtube.com

googlevideo.com

ytimg.com

youtu.be

(You already have ATS exceptions for the YouTube family; App-Bound Domains is a different gate.)

Why this works

The wrapper serves a tiny HTML page from your HTTPS domain (trusted origin) that embeds the official YouTube player on youtube-nocookie.com with playsinline and without the flags that trigger Error 153.

We ensure no CSP or X-Frame-Options collide.

We ensure Capacitor allowNavigation and, if present, WKAppBoundDomains explicitly allow both your proxy page and the YouTube hosts.

Once those three layers agree, YouTube plays happily inside WKWebView.
